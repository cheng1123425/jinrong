## A 流程还原

### A.1 数据载入与字段选择

### A.3 现金流量表单季化（去累计）

- **文中做了什么**：对 10 个 lag 逐层调用 `cal_quarter_data`，用 `season_data == 1` 生成「财年首季」标志，每轮把 `season_data` 减 1、遇 0 回绕为 4，再重算标志：

  ```python
  cashflow_flag = cashflow.season_data.values == 1
  for i in range(10):
      tmp_cash = cal_quarter_data(cashflow.data, cashflow_flag, i, 1, cashflow.season_data.values)
      cashflow.season_data -= 1
      cashflow.season_data = cashflow.season_data.replace(0, 4)
      cashflow_flag = cashflow.season_data.values == 1
  ```

- **口径是否明确**：**否**。这套「季节序号递减 + 0→4 回绕 + 首季标志」是**按财年重置做累计差分**的典型写法，可反推作者**假定现金流字段是累计值（YTD）**；但文中没有一句话写这件事，`cal_quarter_data` 的函数体也完全没给（去累计方向、跨年保护、Q1 是直接取原值还是也做差，均不可见）。
- **是否充分**：**否**。若跨年差分写错，Q1 会出现「本年Q1累计 − 上年Q4累计」的巨额负值，直接污染 y（因变量）本身。
- **证据**：上引循环；`cal_quarter_data` 在全文仅出现 1 次调用、0 次定义。

### A.4 资产负债表科目合计与差分（rcv）

- **文中做了什么**：把 4 个科目相加成「应收+票据+预付+存货」的营运资本占用合计，再逐期做**一阶差分**得到 9 个 Δrcv：`rcv.append((cur - old).values)`，其中 `cur` 为 lag i、`old` 为 lag i+1。
- **口径是否明确**：**是（这一点代码是对的）**。资产负债表科目是**时点值（存量）**，不做单季化、直接跨期差分，方向上正确；`cur/old` 的推进方式（`cur = old`）也保证不会重复取同一期。
- **是否充分**：**部分**。差分方向与存量口径正确，但①4 科目只含资产端（应收+票据+预付+存货），**没有对应的应付账款/应付票据做抵扣**，因此 Δrcv 度量的是「营运资本占用毛额的增长」而非「净营运资本变动」，这一口径选择未说明，会让 γ 吸收本应由应付端解释的部分；②金融股的这 4 个科目结构性缺失，未做处理。
- **证据**：`cur = (balance['account_receivable_lag{}Q'.format(i)] + balance['bill_receivable_lag{}Q'.format(i)] + balance['advance_payment_lag{}Q'.format(i)] + balance['inventories_lag{}Q'.format(i)])`；`rcv.append((cur - old).values)`；`cur = old`。

### A.5 逐标的滚动回归与残差预测

- **文中做了什么**：`Parallel(n_jobs=16)` 对每个交易日 × 每个标的跑一次三参数 OLS：因变量 `train_y`、自变量 `train_x1`（滞后一期 CFO）与 `train_x2`（当期 Δrcv），用 `np.linalg.lstsq` 求解，再外推目标期取残差。
- **口径是否明确**：**是（索引层面）**。这是本审计最容易判错的地方，逐项展开后可以确认三期下标**完全对齐**，见下方 A.5.1。
- **是否充分**：**否**。对齐正确 ≠ 估计可靠：样本只有 4–8 个方程、3 个参数、无正则、无权重、无异常值处理、无季节项。
- **证据**：

  ```python
  max_samples = min(8, len(y) - 1)
  train_y  = y[1:1 + max_samples]
  train_x1 = y[2:2 + max_samples]
  train_x2 = x[1:1 + max_samples]
  coefs, _, _, _ = np.linalg.lstsq(X_train, train_y_clean, rcond=None)
  ```

#### A.5.1 下标展开（n=8 与实际最小 n=4 两种情形）

记 `y[k]` 为 lag k 的单季 CFO、`x[k]` 为 lag k 的 Δrcv，索引 0 = 最新一期。由于 `len(y)=10`（`lag='10Q'` 且循环 `range(10)`），`max_samples = min(8, 10-1) = 8`，**切片阶段 n 恒为 8**；n=4 只可能出现在「8 行里被 NaN 删到只剩 4 行」之后。

| | 切片 | 展开后的期号（k） | 元素数 |
|---|---|---|---|
| `train_y` | `y[1:9]` | k=1..8 → CFO 的 T-1 … T-8 | 8 |
| `train_x1` | `y[2:10]` | k=2..9 → CFO 的 T-2 … T-9 | 8 |
| `train_x2` | `x[1:9]` | k=1..8 → Δrcv 的 T-1 … T-8 | 8 |

逐行看，第 j 行（j=0..7）取到的是：

```
row j : ( y[1+j] , y[2+j] , x[1+j] )
      = ( CFO_{T-1-j} , CFO_{T-2-j} , Δrcv_{T-1-j} )
```

即每一行都满足同一个方程 `CFO_s = α + β·CFO_{s-1} + γ·Δrcv_s`，取 s = T-1-j。j=0 → s=T-1，j=7 → s=T-8。**三期同源、同偏移，无错位。**

n=4 这个数字有两种含义，必须分开说，否则会误判：

- **含义一：`max_samples = 4`（即 `len(y) = 5`）。** 此时 `y[1:5]` 长 4、`y[2:6]` 只能取到索引 2..4 长 **3**、`x[1:5]` 长 4，三列长度 4/3/4，`np.column_stack` 直接抛 `ValueError`。这条路**产不出因子**（沙盒实测见 G14），所以它不是一条真实执行路径。
- **含义二：切片仍按 n=8 完成，但 8 行里被 NaN 删到只剩 4 行**（这是真实会发生的路径，因为守卫条件是 `shape[0] < 4`）。此时保留下来的 4 行是原 8 行方程中的**任意 4 行子集**，第 j 行仍是 `(CFO_{T-1-j}, CFO_{T-2-j}, Δrcv_{T-1-j})`，三期同源、同偏移，**对齐照样成立**——因为删除用的是三列共享的同一个行掩码，不是逐列各自 dropna。

**判定：无论 n=8 还是「有效 n=4」，索引都对；`max_samples=4` 那条分支则是崩溃而不是错位。**

关键实现细节：**NaN 是在切片之后按「行」删除的**（`train_data[~np.isnan(train_data).any(axis=1)]`），三列共用同一个行掩码，所以删行不会造成错行；只有当三列各自 dropna 再拼接才会错位，此处没有犯这个错。

**沙盒验证**（`verify_index.py` 测试 A3，零噪声合成 DGP，真值 α=5、β=0.6、γ=−0.8）：回收系数 α=5.000000、β=0.600000、γ=−0.800000，样本内残差最大 2.1e−14——若存在哪怕一期的错位，零噪声下不可能精确回收三参数。作为反例（测试 A2）：若把 `train_x1` 也写成 `y[1:1+n]`，系数退化为 α=0、β=1.0000、γ=0，方程变成恒等式——这也说明原文那个「多退一期」的写法是必需的、且写对了。

#### A.5.2 预测期口径（对应核查点 5）

`pred_x1 = y[1]`、`pred_x2 = x[0]`、`residual = y[0] - y_pred`。注释写 `# CFO_int_t` 与 `# Δrcv_{t+1}`，看似与下标矛盾，实际是**时间符号约定不同**：只有当 `y[0]` 被定义为「待预测期 t+1」时，`y[1]=CFO_t`、`x[0]=Δrcv_{t+1}` 才成立，而训练集正是 s=t..t-7（`train_y` 注释写「对应 CFO_int_{t-7} 到 …」），预测方程 `CFO_{t+1} = α + β·CFO_t + γ·Δrcv_{t+1}` 与之同构。**结论：索引对、注释也对，两者自洽；错的是读者的默认读法**（把 y[0] 读成 t）。唯一的问题是同一符号 `t` 在两处指不同期，属表述缺陷（G15），不是实现错误。

### A.6 σ 标准化与因子落盘

- **文中做了什么**：用样本内残差的标准差做分母，`o_factor = residual / sigma`，`sigma = np.std(train_residuals, ddof=0)`；`sigma == 0` 时返回 NaN；结果落盘 `g_eps2.parquet`，值列命名为 `g_eps`。
- **口径是否明确**：**否**。σ 是「样本内残差标准差、总体口径（ddof=0）、窗口等于训练窗口」，三点都写在代码里但文中无文字说明；更关键的是**没有说 σ 是用来做什么的**（是做时间序列标准化，还是当作可比尺度）。
- **是否充分**：**否**。σ 的自由度只有 n−3 = 1..5，`ddof=0` 又系统性低估，两者叠加使因子被放大 √(n/(n−3)) 倍，且放大倍数随「有效季度数」变化（详见 B 节 G01）。
- **证据**：`sigma = np.std(train_residuals, ddof=0)  # 总体标准差`；`o_factor = residual / sigma`；`res = pd.melt(res, id_vars='datetime', var_name='code', value_name='g_eps')`；`res.to_parquet('./g_eps2.parquet')`。

## B 缺陷清单

> 分级：P0 使结论整体失效 ｜ P1 显著改变结论方向或量级 ｜ P2 影响可复现性与可信度 ｜ P3 规范性建议。
> **本审计的 P0 为 0 条**，理由见 B.0。共 16 条：P0 0 / P1 6 / P2 8 / P3 2。

### B.0 为什么没有 P0

P0 的三条标准是「前视、错位、样本污染」。逐条核对的结果：

- **错位**：经 A.5.1 逐项展开 + 零噪声精确回收验证，**不存在错位**，可排除。
- **前视**：唯一的通道是 A.2 的 as-of 规则，但 `ReportDataLoader` 源码未给，**无法证实**。按「未披露 ≠ 做错了」，只能定 P2（G07），并写明升级条件。
- **样本污染**：股票池未定义（G10），但「未写明」不等于「没剔除」，同样只能定 P2。

因此本审计不设 P0。**G07 是唯一具备 P0 潜质的条目**：一旦拿到 loader 源码或被要求补做 A.2 的验证（见 G07 验证方式），若发现 `lag0` 是按报告期末而非公告日映射，则 G07 立即升级 P0，且 G01–G06 全部作废重做。

### P1（6 条）

#### G01 σ̂ 双重失真：`ddof=0` 叠加 1–5 个残差自由度

- **证据**：`sigma = np.std(train_residuals, ddof=0)  # 总体标准差`；`if train_data_clean.shape[0] < 4: return np.nan`；`o_factor = residual / sigma`。
- **后果**：三参数回归的残差平方和满足 E[SSE]=(n−3)σ²，`ddof=0` 又除以 n，故 E[σ̂²]=((n−3)/n)σ²，因子被系统性放大 **√(n/(n−3)) 倍**：n=4 → 2.000×、n=5 → 1.581×、n=6 → 1.414×、n=7 → 1.323×、n=8 → 1.265×（解析值，`verify_index.py` 测试 E 已列出）。由于 n 在 4–8 之间随「该股票 8 个候选季度里非缺失的期数」变化，**同一个「预期外现金流」在不同股票上被放大了 1.26 到 2.00 倍不等**，排序结果混入了「数据完整度」这个伪变量；而数据完整度与上市年限、规模强相关，极值组会系统性偏向次新/小盘/数据短的标的。作分层回测时，单调性有可能来自这个尺度差而不是因子信息。
- **修法**：①`ddof=1`；②把最小样本从 4 提到 6（n−3 ≥ 3），不足返 NaN；③更稳的做法是分母改用「同行业×同规模组的中位数 σ̂」做收缩（pooled σ），使分母不依赖单只股票的 4–8 个点；④落盘前对 `o_factor` 做 1%/99% winsorize + 截面 rank。
- **验证方式**：按 `n_clean` 分组（4/5/6/7/8）统计 `|o_factor|` 的中位数，**修好后组间极差应 < 5%**（当前结构下必然呈单调递减，n=4 组约为 n=8 组的 1.58 倍）；同时输出 `n_clean` 分布表，`n_clean < 6` 的标的占比必须披露。若分组后中位数仍随 n 单调下降，说明未修好。

#### G02 `lstsq` 无正则、无权重、无异常值处理、无季节项

- **证据**：`coefs, _, _, _ = np.linalg.lstsq(X_train, train_y_clean, rcond=None)`；`max_samples = min(8, len(y) - 1)`；`X_train = np.column_stack([np.ones(...), train_x1_clean, train_x2_clean])`（仅常数项 + 两个斜率，无季度虚拟变量）；`train_data` 直接取自原始值（无 winsorize）。
- **后果**：3 个参数由最多 8 行、最少 4 行估计，杠杆极高，缺乏任何收缩机制。单季异常——并表范围变化、会计重述、Q4 集中回款、大额预收——即可改写 β 与 γ。因子的预测项是 `alpha + beta*pred_x1 + gamma*pred_x2`，γ 直接乘在 `Δrcv_t` 上，**γ 符号翻转等于因子方向翻转**，而分层/多空结论完全依赖方向。沙盒（测试 A）显示：同一 DGP、8 个观测，单次抽样 β 估到 0.733 而真值 0.600，抽样波动已达 0.13 量级，与 β 本身同阶。另外收现类科目有强季节性（Q4 回款高峰），无季节项时残差里混入季节成分。
- **修法**：①样本窗从 8 个方程扩到 12–20 季（若研报确实规定 10 季，也至少不要只取 8 个方程）；②加 ridge 惩罚（λ 由时间序列交叉验证选，或固定 λ=1 并对 X 标准化）；③对 y 与 x 做 1%/99% winsorize；④加入季度虚拟变量，或先对 y 做季节调整。
- **验证方式**：输出 β、γ 的截面分布（均值/标准差/5%–95% 分位）；**修好的判据是「同一股票相邻两期 γ 同号率 > 90%」且「|β|>1 或 |γ|>10 的标的占比 ≈ 0」**；再对比修前修后的 IC 与分组收益，若差异 > 30% 说明原估计确被少数异常点主导。

#### G03 无截面标准化、无行业/规模中性化

- **证据**：全流程唯一一步变换是 `o_factor = residual / sigma`，随后直接 `to_parquet`；全文无 industry、size、neutral、rank、zscore 任何字样；评价部分直接「分层回测」。
- **后果**：`o_factor` 是「时间序列标准化后的残差」，其截面分布由各股票自身的现金流波动尺度决定，而非统一尺度。行业层面差异极大：地产/建筑/商贸的收现与应计节奏、账期结构完全不同，Δrcv 的季节形态也不同。不做中性化时，**分层排序可能主要在排行业与规模，而不是排「预期外现金流」**。作者报告「近乎完美的单调性」，但没有中性化就无法排除单调性来自行业/规模暴露。
- **修法**：对 `o_factor` 做「行业哑变量 + ln(总市值)」截面回归取残差（或行业内 rank 后再跨行业合并）；行业分类与市值口径需写明。
- **验证方式**：①中性化回归的 R²（**应 < 5%**，若 > 15% 说明原始因子被行业/规模解释掉太多）；②中性化前后分行业 IC 的离散度（应下降）；③中性化前后分组收益的单调性是否保留——若消失，说明原结论主要来自暴露而非因子。

#### G04 「21 日滚动 IC」与「按季更新的因子」叠加，IC 序列高度重叠

- **证据**：原文「毕竟笔者计算的是 21 日滚动 IC」；代码对**每个交易日**都用同一 10 季窗口重跑回归（`for i in range(len(cash))`），故两次财报公布之间因子值恒定。
- **后果**：因子在约 63 个交易日内不变，21 日滚动窗口彼此重叠，同一个截面被重复计入约 3 次；一年的「IC 序列」实际只含约 4 个独立截面（4 个报告期）。因此「回测区间里每一年的 IC 都是正数」这句话的统计含义极弱——每年 4 个独立观测，符号为正不能排除偶然；任何基于日频 IC 序列算出的 t 值都会被重叠放大数倍。这不是实现错误，是**评价方法与因子更新频率不匹配**（作者自己也承认评价体系不合适）。
- **修法**：改用「按报告期取截面」的事件式 IC（每个 report_period 一个截面，共 N 期），或对日频 IC 序列做 Newey-West（lag = 21 或 63）；同时报告独立截面数与 NW-t。
- **验证方式**：同时给出「朴素 t」与「NW-t」；**若两者相差 2 倍以上，即证实重叠严重**；并报告独立截面数（每年应约 4 个）。修好的判据是：结论段落里的显著性表述基于 NW-t 且注明独立截面数。

#### G05 检验矩阵严重不完整，11 项核心指标无一项给出数值

- **证据**：原文「评价分四节，均为截图，正文未给数值」；四节的文字结论分别是「IC 不高」「每一年 IC 都是正数」「换手率没超过 35%」「近乎完美的单调性」。
- **后果**：逐项核对——IC：有图无数值；ICIR：未披露；Newey-West t：未披露；IC 衰减：未披露；分组收益表：未披露（只有净值图）；多空年化：未披露；夏普：未披露；最大回撤：未披露；扣费后收益：未披露；分年度稳健性：仅定性一句「每年 IC 为正」，无数值；样本外：未披露（2017-10 起单区间，无切分说明）。**结论无法被第三方复核，也无法被证伪**——这是审计能给出的最强判断。尤其是「成本未扣」：作者自述 21 天调仓、单次换手 ≤35%，年化换手量级不低但具体数值未披露，未扣费的分层净值不能作为有效性证据。
- **修法**：按上表 11 项逐项补齐数值表；成本假设写明（双边费率、冲击成本、是否按成交额比例），并给出扣费前后两套结果。
- **验证方式**：报告须包含一张「指标 × 数值」表，11 项无空白格；扣费前后多空年化的差额应等于「年换手 × 单边成本」的量级（可自洽校验）；分年度表须覆盖回测区间每一年。

#### G06 未做与已知因子的相关性检验，无法排除是既有因子的变体

- **证据**：原文「与 SUE 或 SUR 类似（作者自述『笔者也不知道什么是 SUE，什么是 SUR』）」；全文无相关性矩阵、无双变量排序、无对已知因子正交化。
- **后果**：该因子在构造上是「CFO 的 AR(1) 残差 + 同期 Δrcv 控制」，与 SUE（标准化预期外盈余）、应计（盈余−现金流）、现金流质量（CFO/净利润）在信息集上高度重叠；而「与 SUE/SUR 类似」是作者自己的定位。不做相关性检验，就无法回答「这是新因子还是既有因子的换皮」。这一点直接影响结论的价值判断，且成本很低（一次截面相关 + 一次双变量排序即可）。
- **修法**：与 SUE、SUR、应计（|应计| 与应计本身）、CFO/净利润、ln(市值)、行业哑变量做月度截面 Spearman 相关矩阵；再做「对 SUE + 应计 + 规模 + 行业正交化后的残差因子」的 IC，看衰减幅度；补 2×2 双变量分组。
- **验证方式**：**若与任一已知因子 |ρ| > 0.7，且正交化后 IC 衰减 > 50%，判定为既有因子变体**；反之可主张增量信息。相关系数矩阵须落盘可查。

### P2（8 条）

#### G07 报告期 → 交易日的 as-of 规则未披露（唯一具备 P0 潜质的条目）

- **证据**：`res = pd.DataFrame(res, index=cashflow.trade_days, columns=cashflow.codes)`；`start = '2017-10-01'`；全文无 `ann_date` / 公告日字段；`ReportDataLoader` 无源码。
- **后果**：若 loader 用「report_period ≤ trade_day」匹配（把季末当作可得日），则每个交易日都在使用**尚未公布**的财报，前视为 1–4 个月，全部 IC、分组、多空结论作废。若用「ann_date ≤ trade_day」，则无前视。**两种实现从外部代码完全无法区分**，这是本流程最大的单点风险。作者「21 日滚动 IC」的表述只能证明索引日频，不能证明 as-of 用公告日。
- **修法**：显式改为 `merge_asof(..., left_on='trade_day', right_on='ann_date', direction='backward')`；因子表同时保留 `report_period` 与 `ann_date` 两列；在 loader 文档里写明「lag0 = 该交易日已公告的最新报告期」。
- **验证方式**：抽 20 只股票、各 4 个报告期，检查「同一 report_period 的因子值**首次出现**的交易日」是否 ≥ 该期 `ann_date`（且为其后第一个交易日）。**只要出现「早于 ann_date」，即为前视，G07 升级 P0**。另一路验证：把 `ann_date` 整体后移 30 天重算，若因子值分布无变化，说明当前实现根本没用到公告日。

#### G08 `lag='10Q'` 与 `lag='9Q'` 语义未定义（可证不构成错位）

- **证据**：`lag='10Q')`（现金流）与 `lag='9Q').to_dataframes()`（资产负债表）；平衡表循环里访问 `balance['account_receivable_lag{}Q'.format(i + 1)]`，i=8 时取 `lag9Q`。
- **后果**：**不造成错位**（推理见下），但参数语义不可复现。推理：若 `'9Q'` 只提供 9 列（lag0..lag8），访问 `lag9Q` 必然 KeyError，代码跑不通；代码既然能跑，`'9Q'` 至少提供 10 列，说明命名是 0-based 且 `lag0` 为最新报告期——两张表的 `lag0` 同期，故 1 期对齐成立。代价是现金流表多取了 1 列（`range(10)` 只用 lag0..lag9），属冗余而非错误。真正的问题是读者无法从文中判断 `lag=NQ` 到底是「N 列」还是「N+1 列」，也就无法复现这层对齐。
- **修法**：文中写明 `lag` 的定义（列数 = 参数值 + 1，0-based，`lag0` 为最新）；或直接把两处参数统一为同一个值。
- **验证方式**：打印两张表 `lag` 列的实际数量，确认 = 参数值 + 1；再核同一股票同一 `report_period` 下 `cash` 与 `rcv` 的 `lag0` 报告期是否相同（相同即对齐）。

#### G09 `cal_quarter_data` 未给出，去累计方式不可核实

- **证据**：`tmp_cash = cal_quarter_data(cashflow.data, cashflow_flag, i, 1, cashflow.season_data.values)`；`cal_quarter_data` 全文仅此一处调用、零处定义；文中亦无「累计值/单季值」的文字说明。
- **后果**：整条单季化链路是黑箱。若差分的「上期」取错（例如跨财年未重置），Q1 单季值 = 本年Q1累计 − 上年Q4累计，会出现巨额负值，直接污染 y；而 y 是回归因变量，一处污染会传导到 β、γ、σ 全部估计。这是「不写就等于没有」的典型：读者无法判断这是研报口径还是作者自创。
- **修法**：贴出 `cal_quarter_data` 源码；用 3 个手算样例（某股票 2019Q1–Q4 的累计→单季）作为文档内嵌校验。
- **验证方式**：对任意 10 只股票，逐年检查「4 个单季之和 == 年报累计值」（误差应 < 1e−6）；且 Q1 单季值不应相对 Q4 出现数量级跳变。任一不成立即去累计错误。

#### G10 股票池完全未写明，金融股口径不适用

- **证据**：`balance = ReportDataLoader.load_data(..., codes=cashflow.codes, lag='9Q')`（股票池隐式继承）；全文无「全A/剔除金融/剔除ST/剔除次新/停牌/涨跌停」任何表述。
- **后果**：①金融股（银行/保险/券商）无「存货」，多数无生产经营性「应收账款」，4 科目之和恒为 0 或 NaN，`Δrcv` 无经济含义——若未剔除，这些标的的因子值度量的是别的东西，混入截面即样本污染；②ST/次新的 CFO 存在重组、补贴、上市前粉饰等异常；③停牌与涨跌停若未处理，回测会包含不可成交标的。以上四点，文中一条都没交代。
- **修法**：写明股票池构建规则与逐条剔除数量（初始 N → 逐条剩余 N）；金融股必须显式剔除（申万一级非银金融 + 银行）。
- **验证方式**：输出股票池构建日志（每步剔除数）；**检查因子表中金融股占比是否为 0**；检查是否存在停牌日仍有因子值且被计入回测的标的（应为 0）。

#### G11 覆盖率与两级丢弃率均未披露

- **证据**：第一级 `if len(y) < 4 or len(x) < 4 or np.isnan(y[0]) or np.isnan(y[1]) or np.isnan(x[0]): return np.nan`；第二级 `if train_data_clean.shape[0] < 4: return np.nan`。
- **后果**：第一级剔除「最新一期 CFO 或 Δrcv 缺失」的全部标的——包括当期未披露、金融股科目缺失、上市不足 10 季者；第二级剔除「8 个候选季度里缺失 ≥5 期」者。两级各丢多少、合计剩多少、占全A比例多少，全部未知。更要紧的是**两级过滤都与「数据完整度」正相关**，幸存样本偏向老公司、大公司，这本身是一种选择偏差，且会通过 G01 的 n_clean 机制二次进入排序。
- **修法**：披露每个交易日有因子值的股票数时间序列、占全A比例、以及两级过滤各自丢弃数与丢弃原因分布。
- **验证方式**：输出 coverage 曲线（应平稳、无断层、无突降）；输出两张丢弃率报表（按原因分类）；**若某段时间 coverage 突然跌破 80%，需给出解释**。

#### G12 因子公式为截图、未转录，代码与研报的一致性无法核对

- **证据**：原文「这种基本面的因子让笔者讲也讲不出来什么东西了」，计算公式用截图给出；「计算公式这里，笔者直接截图了」；「第三段代码是 AI 写的，主要告知输入输出后生成第一版」。
- **后果**：这是全篇最根本的可复现性缺口。审的只是「这段代码做了什么」，无法审「这段代码是否等于研报的 OCFS 因子」。具体不可核对的点包括：σ 的定义（是残差标准差还是别的尺度）、回归是否含常数项、Δrcv 是差分还是水平、是否用 4 季移动和、预测项是否应含滞后 Δrcv。又因代码由 AI 按「输入输出」生成，实现与公式的一致性是**假设**而非事实。
- **修法**：把公式转录为 LaTeX，逐项标注对应的代码行；对公式里出现但代码里没有的项（或反之）逐条说明。
- **验证方式**：做一张「公式项 ↔ 代码行」对照表，两侧须一一覆盖、无孤儿项；由第二人按公式独立实现一版，两版在同一数据上因子值的相关系数应 > 0.99，否则说明代码未忠实实现公式。

#### G13 10 季窗口的截断规则与因子起始日未披露

- **证据**：`start = '2017-10-01'`、`lag='10Q'`；全文无样本起止日、无每期截面数、无「≥10 季」的判定语句。
- **后果**：因子最早可用日不可推（取决于 `start` 是因子起始日还是报告期起始日，以及 10Q 是否向前多取数据）；「要求 ≥10 季历史」在代码里既没有显式判定，也没有对应的 NaN 填充说明，实际是靠数据缺失自然形成 NaN。评审者无法复现样本区间，也就无法复现任何一项统计量。
- **修法**：写明因子表的首末非空日期、每月截面股票数、以及「不足 10 季」标的的处理方式（返 NaN 还是用可得期数）。
- **验证方式**：输出因子表首末非空日期与逐月截面数；**首月截面数应显著小于稳态（因 10 季窗口未满），若首月即接近稳态则说明窗口未生效**。

#### G14 面板不足 10 季时抛异常而非返回 NaN（`len(y) < 4` 守卫无效）

- **证据**：`max_samples = min(8, len(y) - 1)`；`train_y = y[1:1 + max_samples]`、`train_x1 = y[2:2 + max_samples]`；守卫条件 `if len(y) < 4 or len(x) < 4 ...: return np.nan`。
- **后果**：`train_y` 取 `len(y)−1` 个元素，`train_x1` 取 `len(y)−2` 个，两者天然差 1；只有当 `len(y) ≥ 10` 且 `max_samples = 8` 时长度才恰好相等。沙盒实测（测试 C）：`len(y)=9` → `y[1:9]` 长 8、`y[2:10]` 长 7 → `ValueError: all the input array dimensions except for the concatenation axis must match exactly`；`len(y)=8` → 7 vs 6，同样报错。而守卫 `len(y) < 4` 在这些情形**永远不会触发**。真实后果：若某标的只有 9 季历史（次新、或数据源某季整列缺失），不是该标的返 NaN，而是**整个 `joblib` 批次中断**。
- **修法**：守卫改为 `if len(y) < 10 or len(x) < 9: return np.nan`；或把 `max_samples` 改为 `min(8, len(y)-2, len(x)-1)` 使三期自动对齐。
- **验证方式**：单测分别喂 `len(y)` = 10/9/8/4：`len(y)=10` 可返回数值或 NaN；`len(y)`=9/8/4 **必须返回 NaN 且全程不抛异常**。当前实现下 9/8/4 均抛 `ValueError`，即未修好。

### P3（2 条）

#### G15 时间符号约定含糊：`t` 一符多义，易被读成前视

- **证据**：`pred_x1 = y[1]  # CFO_int_t`；`pred_x2 = x[0]  # Δrcv_{t+1}`；docstring「按时间倒序排列（索引 0 最新）」；`train_y` 注释「对应 CFO_int_{t-7} 到 …」。
- **后果**：三者只在「`y[0]` = 待预测期 t+1」的约定下自洽（此时 `y[1]=CFO_t`、`x[0]=Δrcv_{t+1}`），**代码与注释都是对的**。但同一符号 `t` 在「索引 0 最新」与「`y[1]` 是 t」两处指不同期，读者几乎必然误读为「用 t 期数据预测 t 期」（前视），或误判注释有错而把 `pred_x1` 改成 `y[0]`——**那才会真的引入前视**。这是一处会诱导复现者改错的表述缺陷，而非实现错误。
- **修法**：统一记号，例如 `s` 表示期号、`target = y[0]`，注释写成 `pred_x1 = y[1]  # CFO_{target-1}`；正文补一张「下标 ↔ 期号」对照表。
- **验证方式**：在函数内加断言 `assert pred_x1 is y[1]`；由第二人仅按注释重写一版，若其写出 `y[0]` 即证明约定不清。

#### G16 命名与健壮性残留（`g_eps` 命名、docstring 长度错、`np.isnan` 不安全、魔数）

- **证据**：`res = pd.melt(res, id_vars='datetime', var_name='code', value_name='g_eps')`、`res.to_parquet('./g_eps2.parquet')`（EPS 因子的残留命名）；docstring「参数：y, x 均为长度为 10 的列表/数组」（x 实为 9）；`np.isnan(y[0])`（对 object dtype 或 None 抛 TypeError）；`range(10)`、`min(8, ...)`、`shape[0] < 4`、`'lag{}Q'.format(i + 1)` 等魔数散落 5 处。
- **后果**：①值列名为 `g_eps`，读者会误认为这是 EPS 因子，与本因子混淆；②docstring 写 x 长 10 而实为 9，恰好掩盖了 G14 的长度前提；③若数据列含 None，`np.isnan` 直接抛错而非返 NaN；④换窗口长度需同时改 6 处，改漏即静默错位。
- **修法**：值列改名 `o_factor`、文件改名 `ocfs_factor.parquet`；`np.isnan` 换 `pd.isna`；把 10/9/8/4 提为具名参数（`n_lag`、`max_samples`、`min_samples`）。
- **验证方式**：静态检查（全库 grep 不到 `g_eps`）；用含 `None` 的列表跑单测不抛异常；把 `n_lag` 改为 12 后，`len(y)` 与 `max_samples` 自动跟随且单测通过。

## E 最小补丁集（只做 3 件事）

### 第 1 件：把时点钉死（对应 G07）

**做什么**：把 `ReportDataLoader` 的 lag0 改为显式 `merge_asof(direction='backward')` on `ann_date`，因子表同时输出 `report_period`、`ann_date` 两列；加一条断言——同一 `report_period` 的因子值首次出现的交易日不得早于 `ann_date`。

**为什么是这 3 件里的第 1 件**：其余所有缺陷都以「因子在时点上是对的」为前提。若 as-of 用的是报告期末，全部 IC、分层、多空结论作废，G01–G06 的修补全部白做。这是唯一一个「做错了就一切归零」的环节，而且修复成本最低（一次 merge 改法 + 一次抽样验证），**投入产出比最高**。它也是整份审计里唯一能「把 G07 升级为 P0 或把 P0 彻底排除」的动作。

### 第 2 件：修 σ 与最小样本门槛（对应 G01、G14）

**做什么**：`ddof=1`；最小非缺失样本从 4 提到 6（n−3 ≥ 3）；守卫改为 `len(y) < 10 or len(x) < 9 → NaN`；落盘前对 `o_factor` 做 1%/99% winsorize + 截面 rank。

**为什么是这 3 件里的第 2 件**：σ 是分母，直接决定排序。当前 n=4 的标的因子被放大 2.000 倍、n=8 被放大 1.265 倍，**放大倍数与「数据完整度」绑定**，而数据完整度又与上市年限/规模绑定——不修这一条，分层单调性可能整体来自这个伪变量，而不是「预期外现金流」。它属于「算得对不对」层面的错误，比补检验更优先：检验做得再全，分母错了也是精确地测一个错的东西。顺带修掉 G14，可避免换数据源时整批任务崩溃。

### 第 3 件：补最小检验矩阵（对应 G05、G04、G06）

**做什么**：①按报告期取截面算 IC（或对日频 IC 做 NW 调整，lag=63），同时报 ICIR 与 NW-t、独立截面数；②补分组收益数值表 + 多空年化/夏普/最大回撤 + 扣费前后两套；③补与 SUE/应计/CFO÷净利润/ln(市值)/行业的截面相关矩阵，并对这些因子正交化后重算 IC。

**为什么是这 3 件里的第 3 件**：现有结论只有「每年 IC 为正」「换手 ≤35%」「单调性近乎完美」三句定性话，一条都不能被复核或被证伪。补这一组的成本很低（都是已有因子表的再加工，不需要重跑回归），但能把「结论站不站得住」从「作者说」变成「数字说」。其中 NW 调整尤其关键：因子按季更新而 IC 按日滚动，重叠会让 t 值虚高数倍——不修这一条，「每年 IC 为正」的显著性根本无法判定。

**为什么恰好是这 3 件、而不是别的**：三件事分别对应三个不可替代的问题——**能不能用（时点）→ 算得对不对（σ）→ 结论站不站得住（检验）**。中性化（G03）、股票池（G10）、公式转录（G12）都重要，但它们要么依赖第 1 件的结论（股票池要先知道时点才谈得上分层），要么属于「披露」而非「修正」（补文档不改变数值），可以放到第二轮。这 3 件做完，这条复现流程才从「一段能跑的代码」变成「一个可被复核的结论」。
