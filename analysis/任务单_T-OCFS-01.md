# 任务单 T-OCFS-01 · 预期外经营现金流入因子：复现流程审计

**派发方**：项目指挥官（PM）
**执行方**：待派（因子建模师 × 数模分析专家 视角）
**验收方**：项目指挥官
**日期**：2026-11-12

---

## 一、任务目标

对参考文章《JASON's Alpha 因子复现 · Operating cash inflow surprise（预期外经营现金流入）》的**复现流程**做一次完整审计，回答三个问题：

1. 这条流程**已经做了什么**（逐阶段还原，含口径）
2. **还缺什么**（缺环节 / 缺口径 / 缺检验）
3. **哪些做法不完善或有错**（可导致结论无效的缺陷，按严重度分级）

**不做的事**：不重写因子、不重跑回测（当前无 parquet 数据）、不评价"因子好不好"、不给投资建议。

---

## 二、输入材料

- 文章正文（含三段代码）：`analysis/articles/ocfs_article.txt`
- 无需外部数据；所有结论必须基于**文章文本与代码本身**可核实的证据

---

## 三、必须回答的 12 个核查点（逐条给"是/否/无法判断 + 证据"）

### 时点与对齐
1. 因子值使用的是**报告期**还是**公告日**？代码里 `trade_days` 如何取？是否存在用"季末"冒充"可得日"？
2. `lag='10Q'` / `lag='9Q'` 的语义是否一致？现金流量表 10Q 与资产负债表 9Q 混用是否造成错位？
3. 单季度化（`cal_quarter_data`）是否明确：现金流量表原始为**累计值**还是单季值？去累计的方式是什么？

### 回归实现
4. 训练样本的索引对齐是否正确：`y[1:1+n] / y[2:2+n] / x[1:1+n]` 三者的时间下标是否真的一致？
5. 预测时 `pred_x1 = y[1]`、`pred_x2 = x[0]` 与训练期口径是否一致？（注意：代码注释写 `Δrcv_{t+1}`，与实际取值是否矛盾）
6. `min_samples=4`（3 参数 1 自由度）是否足以估 σ？σ 用样本内残差 `ddof=0` 是否合理？
7. 残差除以 σ 后，因子在**截面上**是否可比？是否需要再做截面标准化/中性化？

### 样本与数据
8. 股票池是否写明（全A / 剔除金融 / 剔除ST / 剔除次新 / 停牌与涨跌停处理）？
9. 要求 ≥10 季历史，早期样本如何截断？覆盖率（有因子值的股票数）是否披露？
10. 缺失值处理：`isnan(y[0]) or isnan(y[1]) or isnan(x[0]) → NaN` 会直接丢弃多少标的？是否披露丢弃率？

### 检验
11. 检验矩阵是否完整：IC 之外是否给 ICIR / Newey-West t / IC 衰减 / 分组收益表 / 多空年化 / 夏普 / 最大回撤 / 扣费后收益 / 分年度稳健性 / 样本外？
12. 是否做了**与已知因子的相关性检验**（SUE、SUR、应计、现金流质量、规模、行业）？若高度相关，是否只是既有因子的变体？

## 四、交付物

| 文件 | 内容 |
|---|---|
| `analysis/out_ocfs/流程审计.md` | 主报告：A 流程还原 / B 缺陷清单 / C 缺什么 / D 不可复现项 / E 最小补丁集 |
| `analysis/out_ocfs/gaps.json` | 结构化缺陷清单，字段：`id / stage / severity / title / evidence / impact / fix / verify` |

### 缺陷分级定义（必须遵守）

| 级别 | 定义 | 处理要求 |
|---|---|---|
| **P0** | 会使因子结论**整体失效**（前视、错位、样本污染） | 必须修，修完才能谈效果 |
| **P1** | 会显著改变结论方向或量级（中性化缺失、σ 估计不稳、成本未扣） | 应在下结论前修 |
| **P2** | 影响可复现性与可信度（口径未写明、覆盖率未披露、图未转录） | 补齐即可 |
| **P3** | 规范性建议（命名、注释、目录结构） | 可选 |

### 报告硬性要求

- 每条缺陷必须给**代码片段或原文引用**作为证据，不得只给"建议加强"
- **禁止编造任何数值**（IC、收益、夏普等文章没给的，一律写"未披露"，不得估算）
- 判定"是/否"必须给依据；无法判断的写"无法判断 + 缺什么信息"
- 每个缺陷必须给**可执行的验证方式**（跑什么、看什么数、什么结果算修好了）

---

## 五、验收判据（PM 逐条核对）

1. 12 个核查点全部作答，无跳过
2. 缺陷清单至少覆盖 P0 类（时点对齐、索引对齐）各 ≥1 条
3. 每条缺陷有证据、有影响、有修法、有验证方式（四要素齐全）
4. gaps.json 与 md 报告条目一一对应，数量一致
5. 无编造数值（抽查 3 处"未披露"是否属实）
6. 给出"若只做 3 件事"的优先级排序，且排序理由与 P 级一致
7. 明确列出"不可复现项"（数据不可得 / 图未转录 / 口径缺失）

---

## 六、禁止事项

- 不得改写因子定义后声称"这就是原文"
- 不得用"一般来说""通常"替代对代码的实际核对
- 不得把"文章没写"直接判为"作者错了"——没写 ≠ 做错了，须区分「未披露」与「实现有误」
- 不得给投资建议或推荐该因子
