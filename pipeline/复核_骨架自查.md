## 三、缺陷详情

### 缺陷 1：股票池三字段是死配置（P1）

**证据**

```
$ grep -rn "exclude_st" src/*.py        → 0 处（除 REQUIRED_SPEC 的字符串字面量）
$ grep -rn "min_listed_days" src/*.py   → 1 处（仅 REQUIRED_SPEC）
$ grep -n "def quarterize" src/stages.py → def quarterize(rows, exclude_financial=True)
  但函数体内无任何 exclude_financial 引用
```

**后果**
文档写"剔除金融股"，代码一只没剔。金融股没有"存货"、保险没有"应收账款"，四科目同号相加无经济含义——这类标的会直接污染 Δrcv 与回归系数，但所有门禁都不会报警。

**修法**
S1 真正执行过滤，并输出 `universe.applied / dropped`；新增 G1.3 校验"spec 要求的"与"实际执行的"是否一致。

**验证**
```
过滤前 200 只 → 保留 173 只：financial 16、st 11（含 1 只重叠）、short_history 0
01_coverage.json: universe.applied = {exclude_financial: true, exclude_st: true, min_listed_days: 250}
T10：spec 要求剔 ST 但实际没执行 → G1.3 FAIL ✅
```

### 缺陷 2：判据没从 spec 读（P1）

**证据**

```python
# 修改前 S7
"✅ 达到 0.02" if ic >= 0.02 else "⚠️ 低于 0.02"
"✅ |t|>2"    if abs(t) > 2   else "❌ 不显著"
```

**后果**
`spec.criteria.ic_min` 写在配置文件里、示例 JSON 里，但代码从不读取。**用户以为自己在改判据，实际改不动。** 这比没有判据更糟：它制造了"我控制了口径"的错觉。

**修法**
S7 从 `spec.criteria` 读 `ic_min` / `t_min`，报告里注明判据来源。

**验证**
```
T9：ic_min=0.5 → 报告出现"低于 0.500"判定 ✅
```

### 缺陷 3：G7.2 读错键（P1）

**证据**

```python
metrics 里的键：rebalance_days
gates.py G7.2：m.get("rebalance")
```

**后果**
门禁永远走 `or 21` 的默认值。如果实际是 5 日调仓，年化成本系数应为 252/5=50.4，门禁按 252/21=12 算，**低估 4.2 倍**——本该 WARN 的"成本吃掉一半收益"会被放过。

**修法** 改用 `rebalance_days`；测试 T8 同步改为注入 `rebalance_days`。

### 缺陷 4：`evaluate.rebalance` 名义存在（P2）

**证据**

```python
# 修改前 S5
grid = [i for i in range(250, len(dates)-1) if dates[i][:7] != dates[i+1][:7]]   # 硬编码月末
```

**后果**
spec 里写 `"rebalance": 21` 或 `5`，网格都按月。S6 再从实际间距反推 `rebalance_days`，于是报告显示"22 交易日"，看起来像生效了，其实是被月末网格决定的。

**修法** 网格改为 `range(250, len-1, step)`，`step` 取自 spec。**验证**：`rebalance_days` 现在等于 spec 值 ±0。

### 缺陷 5：责任矩阵是名义的（P2）

**证据**
`pm/派单与验收.md` 的 RACI 只有"数据工程""量纲处理"这类角色名；`run.py` 不读它；`08_gates.json` 里没有 owner 字段。

**后果**
PM 拿到门禁结果，只知道"哪条挂了"，不知道"该找谁"。责任不可追溯，等于没有责任矩阵。

**修法**
新增 `config/owners.json`：每阶段绑定 `owner_role / expert / code / artifact / gates / human_review / reviewer`；`run.py` 读取并在阶段标题打印，每条门禁结果写入 `owner`、`expert`、`human_review`；新增 `--owners` 直接打印矩阵。

### 缺陷 6：S1 缺股票池门禁（P2）

**证据** 原 G1.1 只管"≥50 只 × ≥8 个公告日"，G1.2 只管缺失率。

**修法** 新增 G1.3：比对 `spec.universe` 与 `universe.applied`，不一致即 FAIL；并要求 `dropped` 明细已披露。

## 五、谁来做：代码 / 专家 / 人

| 类型 | 承担者 | 具体内容 | 可否被替代 |
|---|---|---|---|
| **算** | 代码 | 8 个阶段的全部计算（单季化、对齐、回归、标准化、IC、分层、净值、换手） | 不可，也不需要 agent |
| **卡** | 代码 | 26 条门禁，三态判定 | **禁止 agent 改判** |
| **定口径** | 专家 | S0 公式、S2 去累计、S4 回归设定、S5 中性化方案 | 需要专家判断 |
| **解释** | 专家 | 因子是否有经济逻辑、结果是否只是行情 beta | market-regime-analyst 可协作 |
| **放行** | PM | 判 WARN 是否可接受、判"算得对不对"、出验收结论 | **只能 PM** |

**关键结论：agent 不参与"算"和"卡"。** 专家只在"定口径"和"解释"两处介入，PM 只在"放行"一处介入。这是刻意的——如果让 agent 参与门禁判定，它就有动机让自己的结果通过。

## 六、还没做的（诚实清单）

1. **17 条门禁无反例测试**（见第四节）——最大短板。
2. **S6 的分层 t 值没做 NW 调整**：IC 做了，分层没做。21 日持有时重叠 1 期，影响不大但应一致。
3. **无可交易性过滤**：没剔停牌、涨跌停、退市股。G7 只扣成本，没扣"买不进卖不出"。
4. **无样本外切分**：单区间跑完，没有 OOS。
5. **`formula.scale` 占位未实现**：声明了但代码不用，应在接真实数据前删掉或实现。
6. **只有一个公式**（`ocfs_residual`），换因子要改 `stage4_factor`。
7. **数据格式是自定义的**：接真实 parquet 需要一层字段映射。
